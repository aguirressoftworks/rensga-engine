Fixed-point core
Same core systems, integer math
3 wk
▾

The PSX profile's scalar is fixed-point (20.12 for gameplay, 4.12 where the GTE wants it). The core compiles against it unchanged; trig comes from tables. The danger is overflow: multiplying two 20.12 numbers needs a 64-bit intermediate or pre-shifting, so math helpers own that, never game code. Windows/Linux/Android builds of PSX games use the same fixed-point so they play identically.

GPU 2D backend
Ordering tables, VRAM, 320x240
3 wk
▾

New gpu/ backend. The PSX GPU has no depth buffer: each primitive is linked into an ordering table slot by its sort key, and the GPU draws the table back to front. Double-buffered display and draw areas live in the 1 MB VRAM next to texture pages and CLUTs.

7
GTE 3D backend
Transforms, sorting, subdivision, lights
5 wk
▾

The GTE transforms and projects vertices and computes up to 3 lights plus depth-cue fog. Polygons go into the ordering table by average Z. PSX texture mapping is affine, so large polygons near the camera warp badly; fix by subdividing them on the fly and clipping against the near plane. Characters use rigid segmented models, since there's no skinning hardware.

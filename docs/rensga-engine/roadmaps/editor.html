Reflection, serialization and undo
The backbone everything else needs
4 wk
▾

C++ has no runtime reflection, so components declare fields with a macro and a small header-scanner tool generates type info at build time (the same idea as Unreal's header tool). That type info drives the inspector, JSON save/load, prefab overrides and the binary cooker. Every edit goes through a command stack for undo/redo.

4
C++ scripting workflow
Behaviours, hot reload, compile errors
5 wk
▾

Create > C++ Script makes a Behaviour from a template. Game code lives in its own library: the editor rebuilds and hot-reloads it on save. Reload works by serializing all scripted components, unloading the DLL, loading the new one and deserializing, so fields survive. Builds link the same code statically.

Build pipeline
Build Settings, packaging, Build and Run
3 wk
▾

Build Settings window: scenes in build, target, development flag. One click runs the budget validator, cooks assets for the target, compiles scripts statically into the runtime (native build support modules, see Editor 11.5) and outputs the console image, exe, AppImage or APK. Build and Run launches the bundled emulator; an emulator manager shows pinned versions and prompts for the PS2 BIOS.

11.5
Build support modules
Native toolchains and emulators from the Hub, no Docker
3 wk
▾

Each console and cross build is a build support module: a pinned, sha256-verified, prebuilt native toolchain archive for the user's host (Linux or Windows), installed per user from Hub > Modules or `rensga modules install <id>`. Emulators work the same way where an official portable build exists. The pipeline resolves modules by id, offers to install a missing one when Play or Build is pressed, and asks the user to accept a license before anything with one (Google's Android SDK) is installed. CI installs the same modules. Docker stays an optional contributor backend.
